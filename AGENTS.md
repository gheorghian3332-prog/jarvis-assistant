# AGENTS.md — общие правила для всех агентов

Читают все исполнители (Codex, Claude Opus/Sonnet, Gemini). Нарушение = задача не принята.

## Команда и роли
| Логическая роль | Реальный исполнитель | Когда |
|---|---|---|
| Team Lead / Principal Architect | Claude Opus (основная сессия) | архитектура, контракты, интеграция, финальное ревью |
| Backend / Frontend / Windows / Testing Developer | OpenAI Codex CLI (`codex exec`) | основная реализация и тесты |
| Secondary Engineer / Reviewer | Claude Sonnet (субагент) | независимое ревью, поиск ошибок, мелкие модули |
| Second opinion | Codex (`codex-reviewer`) или Gemini CLI | только при спорном ревью |
| AI/Voice, Three.js, Security | роли, не процессы: Codex реализует, Opus/Sonnet проверяет |

Одновременно — не больше 3 тяжёлых задач. Один агент на одну задачу.

## Перед началом задачи
1. Прочитай описание задачи, `ARCHITECTURE.md` и нужный раздел `API_CONTRACTS.md`.
2. Не читай всю кодовую базу — только файлы из карточки.
3. Работай в своём worktree/ветке: `task/<ID>-<slug>`.

## Жёсткие запреты
- Менять файлы вне списка карточки. Особенно `API_CONTRACTS.md`, `shared/` и `ARCHITECTURE.md` — только Team Lead.
- Заглушки, `TODO` вместо основной логики, `pass`, фиктивные данные системы («fake CPU 42%»), закомментированные тесты.
- Выполнять shell-команды из пользовательского ввода без allowlist (см. ARCHITECTURE.md → Безопасность).
- Хранить секреты в коде. Только `.env` (в `.gitignore`).
- Добавлять зависимости без записи в карточке.
- Коммитить в `main`.
- Использовать Блокнот (notepad.exe) в тестах: Win11 Notepad восстанавливает прошлую сессию с файлами пользователя. Для GUI-тестов — собственное тестовое окно
  (минимальный Win32-окно/процесс внутри теста).
- Управлять мышью/клавиатурой пользователя (синтетические клики, SendInput, computer-use). GUI-проверки — только через API окна/процессов или руками пользователя.

## Определение готовности (DoD)
- Rust: `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace` — зелёные.
- Python-воркеры: `uv run ruff check . && uv run mypy . && uv run pytest` — зелёные.
- Frontend: `npm run typecheck && npm run lint && npm test` — зелёные.
- Постоянно работающий код — только Rust. Python не запускается в фоне (только воркеры по требованию с idle-выходом).
- Изменения в постоянном процессе подтверждаются `scripts/profile.ps1`; регрессия RAM/CPU > 20% = не принято.
- Реальная работа на Windows 11 (не мок) для системных модулей; моки — только в unit-тестах.
- Контракты из `API_CONTRACTS.md` соблюдены, схемы сообщений валидируются.
- В отчёте: изменённые файлы, команды проверки и их вывод (кратко), открытые риски.
